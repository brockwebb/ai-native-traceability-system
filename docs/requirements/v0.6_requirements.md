# Requirements: v0.6 — Project Comprehension & Lifecycle Hygiene

**Baseline:** v0.5
**Status:** Planning
**Date:** 2025-02-08

## Overview

v0.6 addresses project lifecycle management and semantic comprehension. Hygiene (init/uninit, artifact removal) before intelligence (audit, bootstrap analysis). The goal: transform registration into understanding.

Design principle: **Every action needs an undo.** init → uninit, add-artifact → remove-artifact. Tools that can't back out aren't tools, they're traps.

Secondary principle: **Registration ≠ comprehension.** 481 artifacts with 0 relationships is useless. Audit and bootstrap analysis bridge the gap between "traced" and "understood."

---

## REQ-UNINIT-001: Project Removal (ants uninit)

**Statement:** The system SHALL provide a command to cleanly remove all ANTS artifacts from a project.

**Behavior:**
- Removes `.ants/` directory (or `.trace/` for pre-v0.5 projects)
- Removes ANTS server entry from `.mcp.json`
- Detects and warns if `.mcp.json` has other MCP servers configured
- Only removes the ants entry, not the whole file
- Two modes:
  - `--confirm`: full removal (directory + config)
  - `--reset`: wipe events but keep config structure

**Interface:**
- CLI: `ants uninit [--confirm] [--reset]`
- MCP: `uninit(mode="confirm"|"reset")`

**Rationale:** Every init must have a corresponding uninit. Currently no way to back out of ants init. Tool wrote to census-mcp-server repo with no undo path. Basic tool hygiene.

**Use cases:**
- "I initialized in the wrong directory"
- "I want to start over with a clean slate"
- "This project doesn't need traceability anymore"
- Testing/development: rapid init/uninit cycles

**Verification:**
- `ants uninit --confirm` removes `.ants/` directory
- `ants uninit --confirm` removes ants entry from `.mcp.json`
- `ants uninit --reset` preserves `.mcp.json` but clears events
- Uninit on project with other MCP servers only removes ants entry
- Warns before destructive operations

## REQ-REMOVE-ARTIFACT-001: Individual Artifact Removal

**Statement:** The system SHALL support removing individual artifacts from the trace graph.

**Behavior:**
- Appends `artifact_removed` event to JSONL (maintains append-only event architecture)
- Does NOT mutate history
- Cascading: removes associated relationships (proposes removal, follows authority model)
- Removed artifacts invisible to queries but event log preserves history

**Interface:**
- CLI: `ants remove-artifact <artifact_id> [--confirm]`
- MCP: `ants:remove_artifact(artifact_id)`

**Rationale:** No way to undo accidental artifact registration. Auto-capture can register files that shouldn't be tracked (temp files, build artifacts, sensitive data).

**Use cases:**
- "I accidentally registered my .env file"
- "This build artifact shouldn't be traced"
- "Wrong artifact ID, need to re-register correctly"
- Cleanup after bulk registration mistakes

**Verification:**
- Artifact disappears from graph queries
- Event log shows `artifact_removed` event
- Associated relationships cleaned up
- Append-only architecture preserved (no deletion from log)

## REQ-AUDIT-001: Project Audit Command (ants audit)

**Statement:** The system SHALL provide a comprehensive audit command that analyzes project health, structure, and quality.

**Analysis Tracks:**

1. **Orphan detection** — Artifacts with no relationships
   - Contextualizes WHY they're orphaned (never imported, test without source, etc.)
   - Distinguishes entry points (legitimate orphans) from dead code

2. **Test coverage gaps** — Source modules without corresponding test artifacts
   - Maps expected test paths (e.g., `src/foo.py` → `tests/test_foo.py`)
   - Flags missing test files
   - Reports test:code ratio

3. **Documentation staleness** — Doc artifacts whose linked source has changed since doc was last modified
   - Compares file mtimes across `documents` relationships
   - Flags docs that haven't been updated after code changes

4. **Naming inconsistency** — Detect mixed conventions across artifact paths
   - snake_case vs camelCase
   - Underscore vs hyphen in filenames
   - Reports by directory/module for actionable fixes

5. **Dead code candidates** — Artifacts not imported/referenced by any other artifact
   - Based on static analysis (not runtime)
   - Excludes entry points, CLI commands, scripts
   - Confidence scoring (high/medium/low)

6. **Relationship completeness** — Percentage of artifacts with at least one relationship
   - Overall stats
   - Breakdown by artifact type
   - Trends over time (if historical audits exist)

**Output:**
- Structured report: `.ants/reports/audit-{date}.md` (Markdown)
- Machine-readable: `.ants/reports/audit-{date}.json` (JSON)
- Summary printed to stdout

**Interface:**
- CLI: `ants audit [--track orphans|coverage|staleness|naming|dead-code|completeness] [--all]`
- MCP: `ants:audit(tracks=["orphans", "coverage", ...])`

**Behavior:**
- Can run individual tracks or all together
- `--all` is default (runs all tracks)
- Generates timestamped reports
- Non-destructive (read-only analysis)

**Rationale:** `ants init` registers files but understands nothing about them. 481 artifacts with 0 relationships is useless. Audit bridges the gap between registration and comprehension. Repeatable — codebases drift back into mess continuously.

**Use cases:**
- "How healthy is my trace graph?"
- "What needs attention before release?"
- "Are we maintaining good practices?"
- CI/CD health checks

**Verification:**
- Audit on dogfood repo produces actionable findings
- Each track runs independently
- Report is parseable (Markdown + JSON)
- Orphan detection distinguishes entry points from dead code
- Coverage track finds missing tests
- Staleness track detects outdated docs

## REQ-BOOTSTRAP-ANALYSIS-001: Intelligent Bootstrap (Enhanced ants init)

**Statement:** The system SHALL support an optional deep analysis phase during init that infers initial relationships and quality assessment.

**Phases:**

**Phase 1 (existing):** Scan files, classify by path pattern, register artifacts

**Phase 2 (new):** LLM-powered analysis
- Reads key files: README, entry points, config, test structure
- Infers initial relationship graph (implements, tests, documents links)
- Generates architecture summary: `.ants/analysis/architecture.md`
- Generates cleanup suggestions: `.ants/analysis/suggestions.md`
- Bootstraps key terms catalog (feeds REQ-CATALOG-001 from v0.5)

**Interface:**
- CLI: `ants init --analyze` or `ants init --deep`

**Behavior:**
- Triggered by `--analyze` or `--deep` flags
- Falls back gracefully if no LLM available (Phase 1 only, no error)
- Can leverage agent teams (Claude Code experimental) for parallel analysis:
  - Agent 1: imports/dependencies
  - Agent 2: test mapping
  - Agent 3: doc coverage
- Progress indicators for long-running analysis
- Results auto-accepted (follows DD-AUTO-ACCEPT-001)

**Rationale:** DeepWiki and similar tools generate documentation from repos but produce wiki pages, not structured relationship data. This builds comprehension directly into the trace graph. Cold-start problem — going from 481 artifacts with 0 links to a useful graph should not require manual relationship entry.

**Use cases:**
- "Initialize a new project with rich context"
- "Bootstrap traceability on an existing codebase"
- "Generate architecture overview automatically"
- First-time setup with minimal manual work

**Verification:**
- `ants init --analyze` on real project produces >0 relationships
- `architecture.md` is generated and accurate
- Suggestions are actionable
- Works without LLM (Phase 1 only, no error)
- Agent teams reduce total analysis time (when available)

## REQ-CLEANUP-SUGGEST-001: Cleanup Suggestions

**Statement:** The system SHALL generate actionable cleanup suggestions based on audit findings.

**Behavior:**
- Consumes output from REQ-AUDIT-001
- Produces prioritized list of actions:
  - Remove dead artifacts
  - Add missing tests
  - Update stale docs
  - Fix naming inconsistencies
- Each suggestion includes:
  - **Severity:** high/medium/low
  - **Effort:** trivial/moderate/significant
  - **Affected artifacts:** specific IDs
  - **Recommended action:** concrete next step

**Interface:**
- CLI: `ants suggest [--from-audit .ants/reports/audit-{date}.md] [--auto-apply]`
- MCP: `ants:cleanup_suggestions(audit_report_path)`

**Auto-apply:**
- `--auto-apply` flag executes trivial suggestions automatically
- Only applies to safe operations (e.g., removing obviously dead artifacts)
- Follows authority model (auto-accepted)
- Confirmation required for medium/high effort changes

**Rationale:** Audit tells you what's wrong. Suggestions tell you what to do about it. Without this, audit is just a report that gets ignored.

**Use cases:**
- "What should I fix first?"
- "Automate cleanup of dead code"
- "Prepare codebase for audit/review"
- Post-refactor cleanup

**Verification:**
- Suggestions reference specific artifacts and actions
- Severity ranking is reasonable
- Auto-apply works for trivial cases
- Requires confirmation for risky changes
- Suggestion format is actionable (not just "fix this")

## Implementation Notes

### Dependency Order

1. **REQ-UNINIT-001** and **REQ-REMOVE-ARTIFACT-001** — Prerequisites (hygiene before features)
2. **REQ-AUDIT-001** — Core capability
3. **REQ-BOOTSTRAP-ANALYSIS-001** — Depends on REQ-AUDIT-001 (reuses analysis tracks)
4. **REQ-CLEANUP-SUGGEST-001** — Depends on REQ-AUDIT-001 (consumes audit output)

### Infrastructure

- No new infrastructure dependencies
- All analysis uses existing NetworkX graph + file system
- LLM-powered features (bootstrap analysis) degrade gracefully when no LLM available

### Agent Teams (Experimental)

- Claude Code experimental feature for parallel analysis
- Natural fit for audit tracks (independent work on different aspects)
- Optional enhancement for REQ-BOOTSTRAP-ANALYSIS-001, not hard dependency
- Known limitations: no session resumption, high token burn

### v0.5 Dependencies

- **REQ-CONTENT-SEARCH-001** (content search) feeds into audit tracks
- **REQ-CATALOG-001** (key terms) feeds into naming consistency checks
- **REQ-RENAME-001** (branding) must be complete — all v0.6 uses `ants:*` naming

### Prior Art & Inspiration

**DeepWiki (AsyncFuncAI/deepwiki-open):**
- Repo → wiki generator
- Good at structure analysis and Mermaid diagram generation
- Produces documentation, not traceability data
- Useful patterns for file filtering and structure inference

**LightRAG (HKUDS/LightRAG):**
- Graph-enhanced RAG with dual-level retrieval
- Evaluated and rejected for v0.5 content search (overkill for grep problem)
- May be relevant for semantic relationship discovery in future versions
- Adds infrastructure complexity that conflicts with zero-dependency principle

**Agent teams (Claude Code experimental):**
- Parallel analysis tracks map well to audit
- Each track is independent work on different aspects
- Natural fit but experimental feature with rough edges
