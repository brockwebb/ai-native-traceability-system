# Requirements: v0.4 — Reports & Visualization

**Baseline:** v0.3.0
**Status:** Planning
**Date:** 2025-02-03

## Overview

v0.4 adds human-facing outputs. The graph has data; now humans can see it. RTM generation, dependency visualization, coverage reports. The "so what" for stakeholders.

---

## REQ-RTM-001: Requirements Traceability Matrix Export

**Statement:** The system SHALL generate a Requirements Traceability Matrix showing requirements → implementations → tests.

**Output formats:**
- Markdown table (default)
- CSV (for spreadsheet import)
- HTML (for stakeholder review)

**Columns:**
- Requirement ID
- Requirement summary (first line or title)
- Implementation artifacts (comma-separated)
- Test artifacts (comma-separated)
- Status (fully traced / partial / orphan)

**Interface:**
- CLI: `trace report rtm [--format md|csv|html] [--output FILE]`
- MCP: `export_rtm(format, output_path)`

**Verification:**
- Generates valid markdown table
- Identifies orphan requirements (no implementation)
- Identifies untested implementations
- CSV exports are importable to Excel/Sheets
- HTML renders correctly in browser

## REQ-DEP-001: Dependency Map Visualization

**Statement:** The system SHALL generate visual dependency maps showing artifact relationships.

**Output formats:**
- Mermaid diagram (embeddable in markdown)
- DOT format (for Graphviz)
- JSON (for custom visualization)

**Features:**
- Filter by artifact type
- Filter by relationship type
- Limit depth (for large graphs)
- Highlight specific artifact and its connections

**Interface:**
- CLI: `trace report deps [--root ARTIFACT] [--depth N] [--format mermaid|dot|json]`
- MCP: `export_dependency_map(root, depth, format, filters)`

**Verification:**
- Mermaid output renders in GitHub/GitLab
- DOT output renders with Graphviz
- Depth limiting works correctly
- Filters reduce output appropriately

## REQ-COV-001: Coverage Report

**Statement:** The system SHALL report traceability coverage gaps.

**Report sections:**
1. **Orphan requirements** - requirements with no `implements` links
2. **Untested code** - modules/functions with no `verifies` links
3. **Undocumented decisions** - decisions not linked to requirements
4. **Proposed links pending** - items awaiting approval

**Interface:**
- CLI: `trace report coverage [--format md|json]`
- MCP: `export_coverage_report(format)`

**Verification:**
- Correctly identifies orphan requirements
- Correctly identifies untested modules
- Counts match manual inspection
- JSON format is parseable

## REQ-IMPACT-RPT-001: Impact Report

**Statement:** The system SHALL generate impact reports for change analysis.

**Input:** Artifact ID or list of artifact IDs

**Output:**
- Direct dependents (1 hop)
- Transitive dependents (full cascade)
- Grouped by artifact type
- Risk assessment (high/medium/low based on count and type)

**Interface:**
- CLI: `trace report impact ARTIFACT [--format md|json]`
- MCP: `export_impact_report(artifact_ids, format)`

**Use cases:**
- Pre-change analysis: "What breaks if I modify this?"
- Release planning: "What's affected by these changes?"
- Stakeholder communication: "Here's the blast radius"

**Verification:**
- Transitive count matches `trace:impact` tool
- Grouping by type is correct
- Risk levels are reasonable

## REQ-DECISION-LOG-001: Decision Log Export

**Statement:** The system SHALL export a chronological decision log.

**Output:**
- Date (from event timestamp)
- Decision ID
- Summary (first line)
- Status (proposed/authoritative)
- Related artifacts

**Interface:**
- CLI: `trace report decisions [--since DATE] [--format md|json]`
- MCP: `export_decision_log(since, format)`

**Verification:**
- Chronological ordering correct
- Date filtering works
- Links to related artifacts included

## REQ-EXPORT-MERMAID-001: Mermaid Graph Export

**Statement:** The system SHALL export arbitrary graph subsets as Mermaid diagrams.

**Parameters:**
- Root artifact (optional, exports full graph if omitted)
- Depth limit
- Relationship types to include
- Artifact types to include
- Direction (upstream, downstream, both)

**Interface:**
- CLI: `trace export mermaid [OPTIONS]`
- MCP: `export_mermaid(root, depth, rel_types, artifact_types, direction)`

**Verification:**
- Output is valid Mermaid syntax
- Renders correctly in Mermaid live editor
- Filters work correctly
