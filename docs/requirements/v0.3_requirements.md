## REQ-INIT-001: One-Command Initialization

**Statement:** The system SHALL provide a single command to initialize tracing in a repository.

**Behavior:**
- Create `.trace/` directory structure
- Auto-detect project type (SE artifacts present? Tests? etc.)
- Select appropriate methodology template
- Run bootstrap scan
- Generate project-scoped `.mcp.json`
- Create CC skill file if CC detected

**Interface:** `trace init` CLI or MCP tool `init_trace()`

**Status:** ✅ Implemented

**Implementation:**
- `trace_core.cli` module with CLI entry point
- `trace_core.init.TraceInitializer` class for initialization logic
- `trace_core.resources` module for bundled templates and skill file
- Package resources bundled via pyproject.toml configuration
- Templates, skill file embedded in package (cross-project usage)
- Auto-detection logic for systems-engineering, agile, lightweight

**Cross-Project Usage:**
- `pip install ai-native-traceability` installs `trace` command globally
- `trace init` works from any directory
- Templates and skill file loaded from installed package resources
- No dependency on source tree

**Verification:**
- `test_req_init_001_creates_trace_dir` - Creates .trace/ directory structure
- `test_req_init_001_detects_se_project` - Detects systems-engineering template
- `test_req_init_001_detects_agile_project` - Detects agile template
- `test_req_init_001_detects_lightweight_project` - Falls back to lightweight
- `test_req_init_001_generates_mcp_json` - Generates valid .mcp.json
- `test_req_init_001_copies_skill_file` - Installs skill file when .claude/ exists

## REQ-SKILL-001: Claude Code Skill File

**Statement:** The system SHALL provide a CC skill file that enables automatic traceability capture.

**Skill behaviors:**
- Auto-register files on create/modify
- Infer relationships from imports, references, mentions
- Propose links with rationale
- Warn before modifying high-impact artifacts
- Remind about pending approvals at session end

**Location:** `.claude/skills/traceability.md` (or project equivalent)

## REQ-AUTO-001: Auto-Registration on File Create

**Statement:** When CC creates or modifies a file, the system SHALL automatically register or update the artifact.

**Mechanism:** CC hook (PostToolUse) or skill-driven behavior.

**Constraint:** Must not require human to remember.

**Status:** ✅ Implemented (MCP Tool + Skill)

**Implementation:**
- `register_file()` MCP tool for zero-friction file registration
- Auto-classifies using template patterns
- Idempotent (safe to call multiple times)
- Skill file RULE 1: ALWAYS register new files immediately
- Actor: "ai:auto-capture" for automatic registrations

**Verification:**
- `test_req_auto_001_register_file_classifies_module` - Classifies src/*.py as module
- `test_req_auto_001_register_file_classifies_test` - Classifies tests/*.py as test
- `test_req_auto_001_register_file_classifies_doc` - Classifies docs/*.md as document
- `test_req_auto_001_register_file_idempotent` - Safe to call multiple times
- `test_req_auto_001_register_file_adds_to_graph` - Actually adds to graph
- `test_req_auto_001_register_file_unknown_defaults_document` - Defaults unknown to document

## REQ-IMPACT-001: Proactive Impact Warning

**Statement:** Before CC modifies an artifact with downstream dependents, the system SHALL surface impact information.

**Behavior:**
- Query `impact(artifact_id)` automatically
- If downstream count > threshold, warn user
- Show what might be affected
- User can proceed or investigate

**Status:** ✅ Implemented (MCP Tool + Skill)

**Implementation:**
- `check_impact()` MCP tool for proactive impact warnings
- Default threshold: 3 downstream dependencies
- Returns warning message if threshold exceeded
- Counts transitive downstream (all affected artifacts)
- Skill file RULE 2: ALWAYS check impact before modifying

**Verification:**
- `test_req_impact_001_check_impact_no_downstream` - Returns empty for isolated artifact
- `test_req_impact_001_check_impact_below_threshold` - No warning when below threshold
- `test_req_impact_001_check_impact_exceeds_threshold` - Warns when exceeding threshold
- `test_req_impact_001_check_impact_custom_threshold` - Respects custom threshold
- `test_req_impact_001_check_impact_transitive` - Counts transitive downstream
- `test_req_impact_001_check_impact_nonexistent_artifact` - Handles non-existent gracefully
