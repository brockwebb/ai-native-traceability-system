# Requirements: v0.5 — Analysis Integration & Enrichment

**Baseline:** v0.4.0
**Status:** Planning
**Date:** 2025-02-03

## Overview

v0.5 integrates external analysis tools for automatic dependency detection. Function-level granularity. Drift detection. The "invisible spider" that enriches the graph without human intervention.

Design principle: **Adopt before create.** Leverage pydeps, pyreverse, import-linter rather than reimplementing static analysis.

---

## REQ-ANALYZE-001: Manual Analysis Trigger

**Statement:** The system SHALL provide a manual command to run dependency analysis.

**Behavior:**
- Invoke configured analyzers (pydeps, pyreverse, etc.)
- Parse output into graph relationships
- Store as `depends_on` links with source="analyzer:<tool>"
- Incremental: only analyze changed files (via git diff)

**Interface:**
- CLI: `trace analyze [--full] [--files FILE...]`
- MCP: `run_analysis(full, files)`

**Use cases:**
- "I don't trust the cache, give me fresh data"
- CI/CD step: `trace analyze && trace report coverage`
- Debugging: "Why doesn't trace know about this relationship?"
- Advanced users wanting explicit control

**Verification:**
- Invokes configured analyzer
- Parses output correctly
- Creates appropriate graph links
- Incremental mode only analyzes changed files
- Full mode analyzes everything

---

## REQ-ANALYZE-002: Init-Time Analysis

**Statement:** The system SHALL optionally run analysis during initialization.

**Interface:**
- CLI: `trace init --analyze`

**Behavior:**
- After standard init, run full analysis
- Bootstrap graph with dependency relationships
- Cold start problem solved: immediate full graph

**Verification:**
- `trace init --analyze` runs analysis
- Graph populated with dependencies after init
- Works on fresh clone

## REQ-ANALYZE-003: Analyzer Configuration

**Statement:** The system SHALL support configurable analyzers per language.

**Configuration:** `.trace/config.yaml` or `trace.yaml`

```yaml
analyzers:
  python:
    tool: pydeps          # or pyreverse, import-linter
    options:
      max-depth: 3
      exclude: ["tests/*", "scripts/*"]
  # javascript:           # future
  #   tool: madge
```

**Behavior:**
- No config = no automatic analysis (system still works via CC inference)
- Config present = analyzer invoked when needed
- Per-language configuration

**Verification:**
- Config file parsed correctly
- Analyzer invoked with correct options
- Missing config handled gracefully
- Invalid tool name errors helpfully

## REQ-ANALYZE-004: Lazy/Background Analysis

**Statement:** The system SHALL support lazy analysis triggered by queries.

**Behavior:**
- CC asks "what depends on this function?"
- Trace checks if dependency data exists and is fresh
- If stale/missing, runs analyzer on that module
- Caches result in graph
- Returns enriched data

**Freshness:**
- Compare file mtime to last analysis timestamp
- Configurable staleness threshold (default: file modified since last analysis)

**Interface:** Transparent - happens automatically during queries

**Verification:**
- Query triggers analysis when data missing
- Query uses cache when data fresh
- Cache invalidated on file modification
- User doesn't see analysis step (invisible)

## REQ-ANCHOR-001: Function-Level Anchors

**Statement:** The system SHALL support function/class-level artifact granularity.

**Artifact ID format:** `file/path.py::function_name` or `file/path.py::ClassName.method`

**Metadata:**
- Line start/end
- Docstring (if present)
- Signature
- Extracted from AST

**Behavior:**
- Analyzer extracts function/class definitions
- Each becomes an artifact with parent relationship to file
- Dependencies link at function level when detectable

**Benefits:**
- "What calls this function?" answerable
- Finer-grained impact analysis
- Docstrings become artifact metadata (rewards good practices)

**Verification:**
- Functions registered as artifacts
- Parent relationship to containing file
- Line numbers accurate
- Docstrings captured

## REQ-DRIFT-001: Content Hash Tracking

**Statement:** The system SHALL track content hashes for drift detection.

**Behavior:**
- Store hash of artifact content at registration
- On query/analysis, compare current hash
- Flag if content changed but relationships not updated

**Hash scope:**
- File-level: hash of file content
- Function-level: hash of function body (AST-normalized)

**Storage:** `content_hash` property on artifact nodes

**Verification:**
- Hash computed on registration
- Hash comparison detects changes
- Unchanged files don't trigger false positives

---

## REQ-DRIFT-002: Drift Detection Alerts

**Statement:** The system SHALL alert when artifacts drift from their traced state.

**Drift types:**
1. **Code drift**: Implementation changed, requirement unchanged
2. **Spec drift**: Requirement changed, implementation unchanged
3. **Stale links**: Linked artifact deleted or renamed

**Interface:**
- CLI: `trace report drift`
- MCP: `check_drift()` returns drift warnings
- Automatic: surface in `health_check()`

**Verification:**
- Detects code changes without requirement updates
- Detects requirement changes without implementation updates
- Reports stale links to deleted files

---

## REQ-ENRICH-001: Docstring Extraction

**Statement:** The system SHALL extract docstrings as artifact metadata.

**Behavior:**
- During analysis, parse docstrings from functions/classes/modules
- Store as `description` property on artifact
- Available for search, reports, context

**Benefits:**
- Better artifact descriptions without manual entry
- Rewards good documentation practices
- CC gets richer context from graph queries

**Verification:**
- Docstrings extracted correctly
- Stored as artifact property
- Searchable via `search_artifacts`

## Implementation Notes

### Tool Integration Pattern

```
[External Tool]     →  [Parser]        →  [Trace Graph]
pydeps --json       →  parse_pydeps()  →  depends_on links
pyreverse -o json   →  parse_pyreverse() → depends_on + contains links
import-linter       →  parse_importlinter() → depends_on links
```

### Performance Considerations

- Incremental analysis via git diff
- Lazy evaluation (analyze on demand)
- Cache with staleness detection
- Background option for large repos (async, non-blocking)

### Graceful Degradation

- No analyzer configured → system works with CC inference only
- Analyzer fails → warn, continue with existing data
- Partial analysis → use what succeeded
