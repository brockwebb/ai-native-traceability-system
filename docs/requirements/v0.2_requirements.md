# Requirements: v0.2 — Infrastructure & Robustness

**Baseline:** v0.1.0 (MVP)
**Status:** Planning
**Date:** 2025-02-02

## Overview

v0.2 focuses on making the trace system robust and self-aware. Health checks, git synchronization, and batch operations. The plumbing before the fixtures.

v0.3 will address adoption and AI-first workflows.

---

## REQ-HC-001: Trace Health Check

**Statement:** The system SHALL provide a health check that validates trace data integrity.

**Validations:**
- All artifact file_paths exist in git
- No broken links (source or target artifact missing)
- No duplicate artifact IDs
- All artifact_types are valid per loaded templates
- events.jsonl is parseable and uncorrupted

**Interface:** MCP tool `health_check()` returning structured report.

**Rationale:** Users need confidence that trace data is valid without manual inspection.

**Status:** ✅ Implemented

**Implementation:**
- `TraceQueries.health_check()` in src/trace_core/queries.py
- `health_check` MCP tool in mcp_server/server.py
- Returns structured report with `healthy` boolean, `issues`, `warnings`, and `summary`

**Verification:**
- `test_req_hc_001_healthy_trace` - Health check passes on valid trace data
- `test_req_hc_001_missing_file` - Detects missing files
- `test_req_hc_001_broken_link` - Detects broken links
- `test_req_hc_001_invalid_artifact_type` - Detects invalid types
- `test_req_hc_001_multiple_issues` - Detects multiple issues
- `test_req_hc_001_structured_report` - Returns structured report

## REQ-CD-001: Git Sync Tool

**Statement:** The system SHALL provide an MCP tool to synchronize trace state with git.

**Behavior:**
- Detect added files → prompt to register
- Detect deleted files → mark artifacts stale
- Detect renamed files → update artifact paths
- Report changes without auto-applying (user confirms)

**Interface:** MCP tool `sync_with_git()`

**Status:** ✅ Implemented

**Implementation:**
- `TraceQueries.sync_with_git()` in src/trace_core/queries.py
- `sync_with_git` MCP tool in mcp_server/server.py
- Returns structured report with added, deleted, and renamed files
- Suggests artifact types for added files using template classification

**Verification:**
- `test_req_cd_001_detect_added_files` - Detects files in git but not traced
- `test_req_cd_001_no_changes` - Reports no changes when in sync
- `test_req_cd_001_multiple_changes` - Detects multiple change types simultaneously
- `test_req_cd_001_structured_report` - Returns structured report
- `test_req_cd_001_artifact_type_suggestion` - Suggests types for added files

## REQ-BA-001: Batch Approval

**Statement:** The system SHALL provide MCP tools for batch approval of proposed links.

**Options:**
- `accept_all_proposed()` — approve all pending
- `accept_by_type(relationship_type)` — approve by relationship
- `accept_by_source(artifact_id)` — approve all from one artifact

**Rationale:** One-by-one approval doesn't scale.

**Status:** ✅ Implemented

**Implementation:**
- `TraceQueries.accept_all_proposed()` in src/trace_core/queries.py
- `TraceQueries.accept_by_type()` in src/trace_core/queries.py
- `TraceQueries.accept_by_source()` in src/trace_core/queries.py
- Three MCP tools in mcp_server/server.py: accept_all_proposed, accept_by_type, accept_by_source
- Batch promotion events persisted to event log with actor="human"

**Verification:**
- `test_req_ba_001_accept_all_proposed` - Promotes all proposed links at once
- `test_req_ba_001_accept_by_type` - Promotes links filtered by relationship type
- `test_req_ba_001_accept_by_source` - Promotes links from specific source artifact
- `test_req_ba_001_accept_all_when_empty` - Handles empty case gracefully
- `test_req_ba_001_accept_by_type_no_matches` - Handles no matches for type
- `test_req_ba_001_accept_by_source_invalid_artifact` - Error handling for invalid artifact
- `test_req_ba_001_events_persisted` - Promotion events written to event log
