## REQ-HC-001: Trace Health Check

**Statement:** The system SHALL provide a health check that validates trace data integrity.

**Validations:**
- All artifact file_paths exist in git
- No broken links (source or target artifact missing)
- No duplicate artifact IDs
- All artifact_types are valid per loaded templates
- events.jsonl is parseable and uncorrupted

**Interface:** MCP tool `health_check()` returning structured report.

**Rationale:** Users need confidence that trace data is valid without manual inspection.

**Status:** ✅ Implemented

**Implementation:**
- `TraceQueries.health_check()` in src/trace_core/queries.py
- `health_check` MCP tool in mcp_server/server.py
- Returns structured report with `healthy` boolean, `issues`, `warnings`, and `summary`

**Verification:**
- `test_req_hc_001_healthy_trace` - Health check passes on valid trace data
- `test_req_hc_001_missing_file` - Detects missing files
- `test_req_hc_001_broken_link` - Detects broken links
- `test_req_hc_001_invalid_artifact_type` - Detects invalid types
- `test_req_hc_001_multiple_issues` - Detects multiple issues
- `test_req_hc_001_structured_report` - Returns structured report

## REQ-CD-001: Git Sync Tool

**Statement:** The system SHALL provide an MCP tool to synchronize trace state with git.

**Behavior:**
- Detect added files → prompt to register
- Detect deleted files → mark artifacts stale
- Detect renamed files → update artifact paths
- Report changes without auto-applying (user confirms)

**Interface:** MCP tool `sync_with_git()`

---

## REQ-BA-001: Batch Approval

**Statement:** The system SHALL provide MCP tools for batch approval of proposed links.

**Options:**
- `accept_all_proposed()` — approve all pending
- `accept_by_type(relationship_type)` — approve by relationship
- `accept_by_source(artifact_id)` — approve all from one artifact

**Rationale:** One-by-one approval doesn't scale.
